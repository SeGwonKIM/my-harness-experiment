# my-harness-experiment

과제 "도구의 불편을 개선 가설로 바꿔 실험하기" 제출물.
지금 쓰는 하네스(Claude Code)에서 겪은 불편 하나를 가설로 바꾸고, 실제로 한 실험을 그대로 기록했다.
하지 않은 것과 확인하지 못한 값도 숨기지 않고 "미확인"으로 적었다.

## 한눈에

| | |
|---|---|
| **불편** | "고쳐줘"라고 자유 텍스트로 요청하면 무엇이 어디까지 바뀔지 미리 알 수 없고, 테스트가 통과해도 맞는지 판단하기 어렵다 |
| **가설** | 같은 fixture·모델에서 search·replace 블록으로 요청하면 자유 텍스트보다 요청하지 않은 파일 수정이 적고, 통과까지 요청 수가 같거나 적다 |
| **고정** | Claude Code, `claude-opus-5-5`, `fixture/` 4개 파일, `test_shop.py` |
| **조작** | 요청 문장 형식 (자유 텍스트 / search·replace) |
| **측정** | 대상 파일 첫 적중, 요청 안 한 파일 수정 수, 통과까지 요청 수, 시간, 수정 횟수, 토큰, 전수 검사 오차 건수 |
| **사전 판정식** | B 가 요청 안 한 파일 수정이 더 적고 통과까지 요청 수가 같거나 적으면 지지, 그 외 기각 (※ 실행 뒤에 작성) |
| **판정** | **보류** — search·replace 조건 미실행, 자유 텍스트 조건의 시작 코드가 fixture 와 달랐고 앞 대화가 남아 있었음 |
| **알게 된 것** | 1원 오차를 놓친 주된 원인은 요청 형식이 아니라 **테스트가 한 경우뿐**이었던 것. 자유 텍스트 조건이 오차를 찾은 건 에이전트가 **전수 검사를 스스로 돌렸기 때문** |

전체 보고서: [`experiment-01.md`](experiment-01.md)

## 핵심 수치

가격 1,000종 × 할인율 101종 = 101,000건을 같은 기준으로 다시 잰 결과 (`traces/verify.py`):

| 코드 상태 | 기존 테스트 | 값이 틀린 건수 | 정수가 아닌 건수 |
|---|---|---|---|
| fixture 원본 | 실패 | 100,000 | 101,000 |
| 한 번 고친 코드 (출처 미확인) | 통과 | **18,347** | 0 |
| search·replace 문장 그대로 | 통과 | 0 | 101,000 |
| 자유 텍스트 조건 실행 결과 | 통과 | 0 | 0 |

자유 텍스트 조건 실행: 61초, 요청 1회, Edit 2회(`discount.py`, `test_shop.py`), 모델 호출 7회, 출력 토큰 2,524.

## 폴더 구조

```
my-harness-experiment/
├── README.md            # 이 파일 — 가설, 설계, 판정, 재검토 조건 요약
├── experiment-01.md     # 실험 보고서 전체
├── traces/
│   ├── timeline.md      # 세션 기록에서 옮긴 실행 궤적
│   ├── states/          # 시점별 discount.py (원본·수정 전후)
│   ├── verify.py        # 모든 상태를 같은 기준으로 재는 스크립트
│   └── verify-output.txt
└── fixture/             # 고정한 작업 입력 원본 (바꾸지 않는다)
```

## 다시 돌려 보기

```bash
python traces/verify.py
```

```bash
cd fixture && python test_shop.py
```
