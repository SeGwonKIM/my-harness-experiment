# 실행 기록 (trace)

Claude Code 세션 기록(JSONL)에서 해당 구간만 골라 옮겼다. 시각은 한국 시간(KST)이다.
로컬 경로는 `1016/...` 처럼 실습 폴더 기준으로 줄였다.

- 도구: Claude Code (데스크톱 앱 Code 탭)
- 모델: `claude-opus-5-5` (기록의 `model` 필드)
- 날짜: 2026-10-16

## 기록 1. 원본 fixture 진단 (11:01:53 ~ 11:02:27)

**요청 (자유 텍스트)**

> (test_shop.py 붙여넣기) 실행하니 오류가 나네 수정할 곳 알려줘

| 시각 | 동작 | 결과 |
|---|---|---|
| 11:01:59 | Bash: 1016 폴더 목록, `discount*.py` 찾기 | `discount.py` `price.py` `shipping.py` `test_shop.py` 확인 |
| 11:02:11 | Bash: 파일 4개 출력 + `python test_shop.py` 실행 | `AssertionError: 2000.0 != 18000` |
| 11:02:27 | 답변 | 대상 파일·줄을 **첫 시도에 맞힘**: `discount.py` 3번째 줄 |

에이전트가 제안한 수정(파일은 고치지 않음):

```python
# 현재
return price * percent / 100
# 수정
return price * (100 - percent) / 100
```

`/ 100` 이면 결과가 `18000.0`(실수)이라 정수가 필요하면 `// 100` 을 쓰라는 설명도 붙였다.
→ 이 제안 문장은 과제의 search·replace 조건 문장과 **글자까지 같다**.

## 기록 2. 출처를 모르는 수정 (11:12 ~ 11:17)

- 11:12 에 `1016/test/`, `1016/test2/` 폴더가 생겼다 (파일 수정 시각 기준).
- 11:16~11:17 에 두 폴더의 `discount.py` 가 아래처럼 바뀌어 있었다.

```python
return int(price * (1 - percent / 100))
```

- 이 수정은 **Claude Code 세션 기록 어디에도 없다.** 사용자도 어떻게 고쳤는지 기억하지 못한다.
  그래서 보고서에서는 "출처 미확인"으로 적고, search·replace 조건의 결과로 쓰지 않는다.
- 기존 테스트(`20000원, 10%` → `18000`)는 통과한다. 그러나 전수 검사에서는 101,000건 중
  **18,347건이 1원 모자란다** (`verify-output.txt`).

## 기록 4. search·replace 조건 실행 (15:13:23 ~ 15:14:23, 60초)

- 사전 판정식을 첫 커밋(`66717ae`)에 고정한 **뒤에** 실행했다.
- `fixture/` 원본을 새 폴더 `run-B/` 로 복사하고, 앞 대화가 없는 **새 세션**에서 요청했다.
- 요청문은 과제 문장 그대로이고, 파일 줄에만 경로를 넣었다 (`## 파일: …/1016/run-B/discount.py`).
  세션 배경 설명으로 "대상 폴더, 커밋하지 말 것" 두 가지만 함께 전달됐다.

**요청 (search·replace)**

```
할인을 적용하면 가격이 이상하게 나와. 아래 변경을 검토하고 반영해서 고쳐줘.

## 파일: …/1016/run-B/discount.py
찾기:
return price * percent / 100
바꾸기:
return price * (100 - percent) / 100
```
